# E1 — 단계별 건수 · S1 신호 빈도 분석 · 관찰 종목 확대

GPT 10/21 제안: 5종목 관찰·삼성전자 1종목 주문으로는 표본이 너무 느리게 쌓임. 관찰 범위를 넓히고 신호 빈도를 숫자로 확인한다.
**전략 조건·주문 허용 범위(005930·1주·최대 1포지션)·안전 장치는 그대로.**

## 1. 단계별 건수 (`domain/research/s1_funnel.py`)

관리자 20:30 스캔마다 작업 기록·일일 보고서·관리 창('오늘 진행' → S1 단계별 건수)에 표시.

```
분석 N → 데이터 준비 → 패턴 PASS → 종목 자격 → 시장 PASS → 손절 기준 → 최종 S1 PASS (순차)
· 시장 조건만으로 제외 K · 독립: 패턴·자격·시장·손절 각각
```
- **순차**: 앞 단계를 통과한 것만 다음 단계에서 셈.
- **독립**: 데이터가 준비된 것 중 그 조건 하나만 본 수(예: 독립 시장 PASS 0 = 시장 판정 자체가 RISK_ON이 아님).
- **시장 조건만으로 제외**: 패턴·자격·손절 기준은 모두 통과했는데 시장 판정 FAIL로만 빠진 수(E2). 시장 판정 불가(UNKNOWN)는 따로 표시.

## 2. S1 신호 빈도 분석 (`tools/s1_frequency.py`, 조회 전용·API 호출 없음)

연구 DB에 이미 있는 일봉으로 과거 거래일마다 운영과 같은 `evaluate_s1`을 다시 계산합니다. 비교 변형은 **측정용**이고 운영 조건이 아닙니다.

| 변형 | 내용 |
|---|---|
| BASE | 운영 S1 그대로 |
| NO_MARKET | 시장 조건만 뺌 |
| MARKET_MIXED_OK | 시장 MIXED도 허용 |
| NO_TREND | 120일선 위·60일선 상승 조건만 뺌 |
| PULLBACK_2_15 | 눌림 2~15일 허용(기본 2~10) |

결과: `reports/research/s1_frequency_<끝날짜>.md`(같은 이름이 있으면 덮어쓰지 않고 `_<시각>_<종목 수>sym`을 붙임, E2)(단계별 건수·주요 탈락 조건·변형별 PASS·시장 판정 분포·종목별), `.csv`(어느 변형이든 PASS인 종목·날짜).

한계: 지금 저장된 수정주가 기준(그날 실제로 보였던 값이 아님), 종목 자격은 최근 종목 목록 기준, 신호 수만 셈(진입·수익 없음).
시장 판정 분포는 종목 구성과 무관하게 두 지수를 날짜마다 직접 계산합니다(E2). 거래일은 KOSPI 지수 일봉 날짜를 씁니다(운영 달력은 2026년만 다룸). 달력이 다루는 구간에서 두 목록이 다르면 보고서에 표시됩니다.

## 3. 관찰 종목 확대 (`tools/watchlist.py suggest` · `add-many`)

- `suggest --kospi 20 --kosdaq 10`: (연구 DB만 읽기 전용으로 엶 — DB를 만들거나 바꾸지 않음, E2) 최신 종목 목록에서 보통주·수집 대상·지금 진입 자격 있음·위험 표시 없음을 시가총액 순으로 고름. 이미 있는 종목은 뺌. **읽기만 합니다.**
- `add-many <코드들> --interest --s1`: 한 번에 추가하고(설정 1버전, 이력 1건) 과거 일봉을 준비합니다. 하나라도 이미 있으면 아무것도 바꾸지 않고 거부합니다.
- 주문 허용은 `settings.yaml`의 `swing_strategy.allowed_symbols`가 따로 정합니다(지금 005930). 다른 종목이 PASS를 받아도 `NOT_ALLOWED`로 기록만 남고 주문하지 않습니다.
