# M3 A2 — 지정가 매수·09:30 미체결 취소·체결 근거

2026-10-13 키움 모의 실측(`tests/fixtures/m1_20261013/`)을 근거로 만든 주문 경로입니다. **전략은 아직 연결하지 않았습니다**
(`NullStrategy` — 주문 의도가 없으면 이 경로는 쓰이지 않음). B(입력 승인·후보 연결)·C(E1·손실 한도·전송 전환)에서 붙입니다.

## 실측으로 확인한 것

| 항목 | 실측 |
|---|---|
| 지정가 접수 직후 미체결(ka10075) | `ord_stt=접수`, `trde_tp=보통`, `ord_pric=207000`, `ord_qty=oso_qty=1`, `cntr_qty=0` → OPEN |
| 취소(kt10003) | `{"ord_no":"0148928","base_orig_ord_no":"0148913","cncl_qty":"000000000001","return_code":0}` |
| 취소 뒤 | 미체결 `oso: []`, 체결(ka10076)에도 원주문·취소 주문 행 **없음**, 잔고 0 |
| 체결 행(ka10076) | 주문마다 한 행. `cntr_pric`=실제 체결가, `tdy_trde_cmsn`/`tdy_trde_tax`=그 주문의 수수료·세금 |

체결 없이 취소된 주문은 어디에도 남지 않으므로, '목록에 없음'만으로는 취소와 주문번호 오류를 구분할 수 없습니다.

## 지정가 매수

- `OrderIntent(..., order_type="limit", limit_price=...)` — **매수만**, KRX 호가 단위에 맞는 양의 정수. 매도·손절은 시장가.
- 안전 한도 금액 = 지정가 × 수량(시장가 여유 1%를 더하지 않음 — 체결가는 지정가 이하).
- 키움 요청: `trde_tp "0"`, `ord_uv`=지정가(기존 `KiwoomBroker.place_order` 그대로).
- 원장 추정가·미체결 예약금은 지정가 기준(보수적).

## 진입 마감 09:30 취소 (`session.entry_cancel_at`, 기본 "09:30", ""면 끔)

1. 09:30 이후 새 지정가 매수 의도 → `ENTRY_WINDOW_CLOSED`(전송 없음).
2. 09:30 이후 폴링마다: **이 실행이 낸** 지정가 매수 중 끝나지 않은 주문(BUY_PENDING 또는 BUY orphan)의 남은 수량을 취소 요청.
   시장가 주문·재시작 전 주문은 건드리지 않음(재시작하면 미해결 주문은 ERROR로 복원 → 사람 확인).
   신규 매수 중단·주문 중단 중에도 취소는 함(노출을 줄이는 쪽).
3. 취소 요청 결과
   - 접수 → 다음 체결조회에서 판정
   - 거절 → 체결이 먼저였을 수 있음. 다음 폴링에 다시(최대 3회)
   - 응답 불명 → **다시 보내지 않음**, 사람 확인
4. 판정(`domain/service/buy_cancel.py`) — 확정은 아래를 **모두** 만족할 때만:
   - 우리 취소가 그 원주문번호로 접수됨 — 응답의 `base_orig_ord_no`가 원주문번호와 같고 `cncl_qty`가 요청 잔량과 같음
     (둘 중 하나라도 없음·0·다름이면 미확정)
   - 원주문 행이 미체결·체결 어디에도 없음
   - 잔고가 주문 직전 수량 그대로

   | 판정 | 처리 |
   |---|---|
   | CANCEL_CONFIRMED | 상태머신 `confirm_buy_cancelled` → FLAT(또는 기존 보유 OPEN), orphan 해제, 계좌 신규 매수 다시 허용 |
   | FILLED(취소보다 체결 먼저) | 기존 체결 확정 경로(잔고 일치 시) |
   | STILL_OPEN | 아직 반영 전 — 상태 유지, 다시 확인 |
   | UNRESOLVED(부분 체결 행·잔고 변화·응답 불명·거절 뒤 사라짐 등) | 상태 유지, `[BUY_CANCEL_UNRESOLVED]` — HTS 확인 후 ack_orphan |
5. 감사 기록 `data/buy_cancels.jsonl`(요청·확정·미해결). 상태 복원에는 쓰지 않음. 실행기 상태 파일의 `buy_cancels`에도 표시.

부분 체결 행 모양은 아직 실측하지 않았습니다 — 부분 체결이 섞이면 자동 확정하지 않습니다.

## 체결 근거 (실제 체결가·수수료·세금)

- 원장(`fill_ledger.jsonl`)은 그대로 append-only. 주문 전량이 한 사건으로 끝나면 실행기가 그 주문의 ka10076 행을 먼저 보고,
  맞으면 원장에 **실제 체결가(BROKER_FILL)**로 기록, 수수료·세금은 `data/fill_evidence.jsonl`에 남김.
- 체결조회 행은 **주문번호(앞자리 0 무시)·종목·방향·수량·가격**이 모두 맞을 때만 원장에 씀 — 원장에 쓰기 전에 검사.
- 조회 실패(429 등)·행 없음·불일치 → 예전처럼 기록(매수 잔고 역산 / 매도 추정)하고, 한 폴링에 한 건씩 간격을 늘리며
  (60·120·240…초, 최대 15분) 최대 5회 다시 확인 → 찾으면 **근거 기록만 추가**(원장 사건을 다시 쓰지 않음 — 중복 BUY/SELL 없음).
- 근거 파일 저장 실패 → 확인한 근거를 저장 재시도 목록에 두고(다시 조회하지 않음) 간격을 늘리며 최대 10회 다시 저장.
  같은 사건에 다른 근거가 이미 있으면(충돌) 재시도하지 않고 사람 확인. 저장 재시도는 체결조회 한도를 쓰지 않아 다른 사건 확인을 막지 않음.
- 미확인 사건·저장 대기·최근 문제는 실행기 상태 파일 `fill_evidence`와 관리 창 주문 탭에 표시.
- 보고서: 당일 실제 비용(수수료+세금, 근거 n/m건), 근거 읽기 실패·충돌 경고. Base/Stress 차감은 모델 계산임을 표시.
  관리 창 실현 손익: 양쪽 근거가 있으면 실제 비용·비용 후 손익, 없으면 '미확인'.
- 번들(`app.reports.export_bundle`, 관리 창 저장): 원장 + `fill_evidence.jsonl` + `buy_cancels.jsonl`(+ 실행 모드 표식) — 번들만으로 보정 가격 재현.
- 보고서·관리 창은 근거 기록을 원장 사건에 겹쳐 실제 체결가로 계산(주문번호·종목·방향·수량이 같을 때만). 수량·보유 계산은 그대로.
- 재시작·수동 주문 등으로 빠진 것: `python tools/paper_order.py confirm-fills`(미리보기) → `--confirm`(기록).
  **오늘 체결만** — 키움 주문번호는 날마다 다시 쓰므로 전날 사건에 오늘 행을 붙이지 않음.
