# M3 B — 20:30 스캔·08:40 입력 재확인·후보 승인·S1 그림자 운영

GPT 최소판 요청 2(일봉 승인과 읽기 전용 후보 연결). **실제 주문은 아직 없음** — `swing_strategy.mode: shadow`는 의도를 만들고
안전 한도까지 판정한 뒤 전송하지 않고 기록합니다. `paper`(실제 모의 전송)는 C(E1 청산·일일 손실 한도) 전까지 기동 거부.

## 하루 흐름 (D = 오늘, t = 직전 거래일)

| 시각 | 누가 | 무엇 |
|---|---|---|
| t 20:30 | 관리자 CLOSE_PREP | 지정 종목 일봉 준비 → S1 스캔(완성 기준 마감 + 300분). 이전 18:10(160분) 스캔은 계약이 달라 **잠정 관찰로 보존**(승인 안 함) |
| D 08:40~08:55 | 관리자 INPUT_CHECK | 후보마다 스캔이 쓴 입력 창(종목·지수 300세션)을 다시 받아 비교 → STABLE / INPUT_CHANGED / CHECK_FAILED (`input_check` 표, 연구 DB 불변). 실패면 기한 안에서 다시, 기한 넘기면 MISSED |
| D 09:05 | 관리자 OPEN_CHECK | 개장 + 5분 가격 기록(A5) — WITHIN_CAP 등 |
| D 09:05~09:30 | 실행기 S1 전략 | 후보 승인(아래) → 주문 직전 현재가·최우선 매도호가 재확인 → 1주 상한 지정가 의도. 그림자면 기록만 |
| D 09:30 | 실행기 | 진입 마감(이후 지정가 매수 의도 거부, A2의 미체결 취소) |

20:30은 **공급자 확정값 보장이 아닙니다**. 그래서 08:40에 다시 받아 같은지 확인하고, 다르면 그날 그 종목은 진입하지 않습니다.

## 후보 승인 (`app/candidates.py`, 관리자 DB `mode=ro`)

모두 만족해야 승인 — 하나라도 아니면 사유와 함께 제외(`strategy_decisions.jsonl`, 관리 창).

| # | 근거 | 조건 |
|---|---|---|
| 1 | OPEN_CHECK·D | COMPLETE (아니면 WAITING — 다음 폴링에 다시 읽음) |
| 2 | A5 후보 목록·D | 상태 OK, 신호일 = 직전 거래일 |
| 3 | 스캔 실행 | COMPLETE·같은 계약·개장 전 저장 완료·완성 기준 ≥ 300분(`PROVISIONAL_SCAN`) |
| 4 | S1 대표 기록 | PASS·final·actionable, 실행·입력 해시·계약 일치 |
| 5 | 게이트 | **같은 스캔 실행**의 개장 전 SCAN 게이트 통과 ∧ OPEN 게이트 통과 |
| 6 | 입력 재확인 | **같은 스캔 실행**의 종목·지수 마지막 결과 STABLE, 확인·저장이 **08:40 ≤ · < 08:55**(달력 개장 기준) |
| 7 | 개장 가격 | OPEN_CHECK 작업의 확인 종류(OPEN+5m)만, fetch OK·**ON_TIME**·WITHIN_CAP, 목표 시각 = 달력 개장 + 5분 |

추가 대조(C1, GPT 검토 R2~R4): 후보 목록의 개장 시각 = 달력 개장, OPEN_CHECK 작업 계약 = 후보 목록 계약(아니면 ERROR).
관리자도 기한 뒤에 끝난 입력 재확인 행을 `LATE:<결과>`로 남겨 승인 근거가 되지 않게 함.
| 8 | 가격 | 지정가(진입 상한 호가 내림) > 참고 손절가 |

DB를 못 읽으면 ERROR — 신규 매수만 보류(보유 청산·주문 복구와 무관).

## S1 진입 전략 (`app/s1_strategy.py`)

- 진입 09:05 ≤ 지금 < 09:30(`session.entry_cancel_at`), 정규장, **1주**, 최대 보유 1(보유·미해결 주문이 있으면 없음), 추가 매수 없음.
- **승인은 폴링마다 다시 읽음**(C1 R1) — 그 폴링 결과가 ERROR·WAITING·거부면 의도 없음. 이미 쓴 신호 키는 되살리지 않음.
- 주문 직전: 현재가 > 참고 손절가 ∧ 현재가 ≤ 진입 상한 ∧ 최우선 매도호가(ka10004) ≤ 지정가. 아니면 그 폴링 보류(사유 기록 — 같은 사유 반복 기록 없음).
- **같은 신호는 한 번만**: 의도를 넘기기 전에 신호 키 기록(`data/strategy_signal_keys_<모드>.jsonl`). 취소로 FLAT이 돼도, 한도에 막혀도 다시 진입하지 않음. 그림자와 전송 키는 파일이 따로.
- 실행기 수량 상한 검사(`QTY_LIMIT`, 1주) — 전략과 별도로 한 번 더.

## 켜는 법 (그림자)

`config/settings.yaml` 끝에 추가(나머지 값은 그대로):

```yaml
swing_strategy:
  mode: shadow        # off(기본) / shadow / paper(C 전에는 기동 거부)
```

기록 파일(모두 `data/`, append-only): `shadow_intents.jsonl`(의도·판정 — 전송했을 것/차단 사유), `strategy_decisions.jsonl`(후보 상태·보류 사유),
`strategy_signal_keys_shadow.jsonl`. 관리 창 '오늘 진행'에 입력 재확인 결과와 그림자 의도 수.
